## 阶段 1：问题 → 数据公理

**问题**：闭环控制水厂中，未来 7-19 时出厂 NTU 如何预测？哪些因素真正驱动浊度超标？

**数据公理**（观察层）：
- FILT_NTU 自然三级分布（≤0.05: 49% / 0.05-0.15: 30% / >0.15: 21%），低值区仅 4 个离散值（传感器精度）
- 舒适区 FILT→NTU r≈0.01-0.03 完全解耦；应力区 r=0.79-0.81 物理信号显现 → **信号强度随浊度 regime 跃迁**

## 阶段 2：假设 → 可验证主张

| 假设 | 验证方式 | 结果 |
|------|------|:---:|
| 黑箱 ML 可捕捉闭环保真信号 | 101 维 XGBoost + SHAP | ❌ R²=0.34（全量） |
| CSTR 描述 FILT 递推 | 灰箱拟合 | ❌ R²=-5.7（结构性错误） |
| **CSTR 描述 NTU（清水池混合）** | 段2 公式扫参 | ✅ R²=0.727→0.807 |
| 时滞可由统计方法识别 | CCF/MIC/TE 三法 | ❌ 全部 τ*=0（闭环掩蔽①） |
| 物理参数可辨识 | Langmuir 7 参数扫 τ | ❌ 差异<0.004（闭环掩蔽②） |
| 深度学习优于线性 | 4 层 TCN+注意力 | ❌ R²=-0.15 < AR(6) 0.52（闭环掩蔽③） |

## 阶段 3：证据 → 判别实验

### 转折点 1：CSTR 用错对象（修正=发现入口）
- 教训：物理模型必须先选对状态变量——清水池混合（NTU 递推）≠滤池穿透（FILT 自 AR）
- 判别实验：CSTR 套 FILT（-5.7）vs 套 NTU（0.727）→ 结构不是参数问题

### 转折点 2：τ 不可辨识是系统属性不是方法缺陷
- 伪数据验证（τ_true=2 可识别）排除"方法错误" → 实数据不可辨识 = 闭环系统设计目标
- 转向：softmax 可学习 τ₁（Q1 内部）+ 事件 CCF 分水位（只有中水位滤池穿透事件暴露弱信号）→ **三源交叉得 τ=4h**

### 转折点 3：分层再建模（Q1 三级 / Q3 四层路由）
- Q1：T1 经验采样（JS=0.05 vs 高斯 0.64）、T2 对数压缩（RMSE↓20%）、T3 CSTR+反馈
- Q3：A 持久 / B 混合(α=0.34) / C_strong CSTR / C_weak 阻尼(γ=0.25) → 分层增益 0.195→0.397→0.485→0.602

### 转折点 4：参数 regime 依赖（A 分层 + Balance Detector）
- 分 tier A（400/250/30）：0.727→0.783 → Balance Detector（(RL-6.09)(Q-44) 符号）：→0.807（in-sample）
- 物理含义：清水池在均衡态全池混合 vs 失配态短流（67% 时间失配）——13× regime 切换

### 转折点 5：闭环掩蔽效应收束（五重证据链）
- 统计① → 物理② → 学习③ → 诊断④（方向不对称=诊断非预测特征）→ 结构⑤（CSTR θ 已编码流态）
- 2026-07-27 补充：NN 可学习 β/θ/路由权重全部 FAIL（0.588/0.091 < 手调）— 第六、七重证据
- **结论转为论文最强者论点**：识别"不可识别"本身就是发现；系统性能上限由信息结构决定

### 转折点 6：口径诚实化（sum_13）
- 0.807 是 in-sample → 补诚实 TS-CV 0.737；0.602 是 oracle → 补部署口径 0.485
- 数字总表 = 唯一数字源；修正历史 M1-M4 可追溯（口径声明大全）

## 阶段 4：应用闭环
