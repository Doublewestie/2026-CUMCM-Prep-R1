## 三、沉淀：本次审查产出的 Method 纪律（供未来所有 skill 撰写/审查）

1. **写 skill = 写高层思维**：正文主体（信条/机制/DoD）只承载可迁移的思考方式；
   "怎么想、怎么判断、怎么守门"，不写"这个项目怎么做的"
2. **例子是抓手不是规范**：案例锚点/示例可以举（项目实例、数字、术语均可），
   但必须处在"案例/示例"语义语境（案例锚点表、示例列、教学示例行），
   并让人一眼看出"这可以换成别的"
3. **执行痕迹绝不入 skill**：版本号（v2/草稿层）、草案文件名、个人文件名、
   仓库/库路径——这些是开发期脚手架，进 skill 即污染
4. **署名纪律**：涉及人物的案例（如"建模手答辩发言稿"）用角色名
   （建模手/论文手/答辩人）而非真名
5. **审查触发**：新 skill 成稿 / 大规模迁移 / 用户对"为什么 skill 里有这个"质疑时，
   按三层标准通篇审查；修复走双目录×双项目四份镜像 + md5 对账
